# S0.3 — Zed registration (dev extension alongside clojure-lsp)

> Session decision (2026-09-10): no released Zed covers what we need to verify,
> so we install Zed **built from the vendored `repos/zed`** (@ `52b2927a1b`,
> 2026-09-09). The extension targets the official Clojure extension (already
> installed on this machine) for the language/grammar and registers `zrepl` as
> a **second** language server for Clojure. Milestone entry in
> `docs/ai/plan.md` (S0.3) is superseded by this document.

## Decisions

| Topic          | Decision                                                                                                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Extension type | Dev extension (WASM, Rust) — installed via `Extensions → Install Dev Extension`; no marketplace publishing in the spike                                                                |
| Language       | Do **not** define `languages/clojure/` or a grammar — the official `clojure` extension provides language `Clojure` + grammar; we reference it by name                                  |
| Registration   | `extension.toml` declares `[language_servers.zrepl] languages = ["Clojure"]`; Zed starts all _available_ servers for a language unless disabled                                        |
| Server launch  | Primary: `lsp.zrepl.binary.path` settings override → `bin/zrepl` launcher. Extension `language_server_command` reads `LspSettings` and errors with a clear message when unset          |
| Extension API  | Path dependency on `repos/zed/crates/extension_api` — version **0.8.0** with `publish = false` (not on crates.io), so the WIT world matches the host we build (`since_v0_8_0`) exactly |
| Rust toolchain | mise-managed: rust **1.97.1** (same pin as `repos/zed/rust-toolchain.toml`) + target `wasm32-wasip2`; `profile = "minimal"`                                                            |
| Launcher name  | `bin/zrepl` — one entry point from day one: `zrepl lsp` starts the LSP server; later CLI verbs (`eval`, `connect`, …) land in the same script                                          |
| Project root   | Spike launcher `cd`s into the zrepl checkout (classpath always correct, cwd-independent); S0.5 will use `initialize` params `rootUri` for `.nrepl-port`                                |

## Toolchain (`mise.toml`)

```toml
[tools]
rust = { version = "1.97.1", profile = "minimal", targets = ["wasm32-wasip2"] }
```

- Pin **equals** `repos/zed/rust-toolchain.toml` (`channel = "1.97.1"`, targets
  include `wasm32-wasip2`) — mise sets `RUSTUP_TOOLCHAIN` for the project, which
  would otherwise override the file; with equal pins there is no conflict. If
  the vendored Zed pin ever moves, move this pin with it.
- mise's rust backend drives rustup against the standard `~/.rustup` /
  `~/.cargo`; the toolchain + target already exist on this machine, so
  `mise install` is idempotent.
- New tasks: `zed:build` (build Zed from `repos/zed`, `cargo build --release
-p zed`; one-off ~30–60 min) and `zed:ext:check` (`cargo check --target
wasm32-wasip2` in `zed-extension/`, fast type-check).

### `zed-extension/extension.toml`

```toml
id = "zrepl"
name = "zrepl"
description = "Interactive REPL for Clojure: eval forms in Zed via nREPL"
version = "0.0.1"
schema_version = 1
authors = ["..."]
repository = "https://github.com/just-sultanov/zrepl"

[lib]
kind = "Rust"

[language_servers.zrepl]
name = "zrepl"
languages = ["Clojure"]
```

- `languages = ["Clojure"]` must match the `name` field of the language
  `config.toml` shipped by the official clojure extension (verified locally:
  `~/.local/share`… `extensions/installed/clojure/languages/clojure/config.toml`).
- No `[grammars.*]`, no `languages/` directory, no `[[capabilities]]` —
  the extension spawns nothing itself; returning a `Command` from
  `language_server_command` is not gated by capabilities.

### `zed-extension/src/zrepl_extension.rs` (sketch)

```rust
use zed::{settings::LspSettings, Command, Extension, LanguageServerId, Result, Worktree};
use zed_extension_api as zed;

struct ZreplExtension;

impl Extension for ZreplExtension {
    fn new() -> Self {
        Self
    }

    fn language_server_command(
        &mut self,
        language_server_id: &LanguageServerId,
        worktree: &Worktree,
    ) -> Result<Command> {
        if language_server_id.as_ref() != "zrepl" {
            return Err(format!("unknown language server: {language_server_id}"));
        }
        let binary = LspSettings::for_worktree("zrepl", worktree)?
            .binary
            .ok_or("configure lsp.zrepl.binary.path in settings.json")?;
        let path = binary.path.ok_or("lsp.zrepl.binary.path is not set")?;
        Ok(Command {
            command: path,
            args: binary.arguments.unwrap_or_default(),
            env: binary.env.unwrap_or_default(),
        })
    }
}

zed::register_extension!(ZreplExtension);
```

(`LspSettings::for_worktree` and `CommandSettings { path, arguments, env }`
verified against `crates/extension_api/wit/since_v0.8.0/settings.rs`.)

### `bin/zrepl` (launcher)

```bash
#!/usr/bin/env bash
set -euo pipefail

ZREPL_HOME="$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)"

case "${1:-lsp}" in
  lsp) cd "$ZREPL_HOME" && exec clojure -M -m zrepl.main ;;
  *)   echo "usage: zrepl [lsp]" >&2; exit 2 ;;
esac
```

- `cd` into the checkout guarantees the zrepl classpath regardless of Zed's
  spawn cwd; `.nrepl-port` discovery switches to `rootUri` in S0.5.
- Zed merges the login-shell environment into spawned servers
  (`lsp_store.rs:754`, `delegate.shell_env()`), so mise's `clojure` shim should
  be visible; if not, fall back to `exec mise exec -- clojure -M -m zrepl.main`.

### `zed/settings.json` (snippet)

```json
{
  "lsp": {
    "zrepl": {
      "binary": {
        "path": "~/ws/projects/zrepl/bin/zrepl",
        "arguments": ["lsp"]
      }
    }
  }
}
```

- `binary.path` supports `~/` expansion and worktree-relative paths
  (`worktree.rs:2933`, `resolve_relative_path`).
- When `binary.path` is set, Zed uses it **directly** and never calls the
  extension's `language_server_command` (`lsp_store.rs:725-758`) — the settings
  path is the primary mechanism, the Rust fallback is only a guard.

## Verified facts (from repos/zed @ 52b2927a1b)

- Dev extensions: `zed::InstallDevExtension`, Zed compiles the extension itself
  (needs `cargo` + `wasm32-wasip2`); docs `developing-extensions.md:29-35`,
  target auto-installed for rustup setups.
- A language server is registered per `(server name, language name)` from the
  manifest — no ownership of the language required
  (`extension_host.rs:1658-1666`); languages/grammars remain owned by the
  official clojure extension.
- All _available_ servers for a language start unless explicitly disabled —
  `resolve_language_servers` appends the rest
  (`language_settings.rs:378-420`); Clojure's config has no
  `scope_opt_in_language_servers`, so `zrepl` starts automatically.
- Two servers per language are supported; `executeCommandProvider` commands
  from all servers merge in the picker (plan.md "Verified facts").
- Extension API: vendored Zed hosts `since_v0_8_0` WIT (`wit.rs:24`);
  `zed_extension_api` 0.8.0 is `publish = false`
  (`crates/extension_api/Cargo.toml:9-10`) → path dependency is the only way to
  match exactly; the `zed:api-version` custom section
  (`extension_api.rs:350-353`) enforces the match at load time.
- `LspSettings::for_worktree` + `CommandSettings` shape:
  `crates/extension_api/wit/since_v0.8.0/settings.rs:17-44`.

## Risks

- **Zed build cost**: one-off ~30–60 min release build of `repos/zed`; disk
  heavy. Only affects step 3.
- **`clojure` visibility in Zed env**: mitigated by Zed sourcing the login
  shell env; fallback documented (`mise exec`).
- **Path dependency on gitignored `repos/`**: a fresh clone cannot build the
  extension without vendoring Zed. Spike-only; switching to crates.io
  `zed_extension_api` (next published version) happens at M4.3/publish.
- **Rebuild loop**: dev extension wasm is rebuilt on re-install/rebuild action,
  not on file save — after edits, repeat step 4.
- **Load order**: zrepl's server registration does not require the Clojure
  language to exist first (mapping is stored unconditionally); low risk, will
  confirm at runtime.
- **Two inlay hint providers / execute command providers**: merge, no
  collision thanks to the `zrepl/` prefix (plan.md risk, re-verified here).
