# S0.4 — Buffer tracking (didOpen / didChange / didClose)

> Session decision (2026-09-10): buffer state lives in the existing
> `zrepl.server` state atom — no new namespace, no extra indirection. The
> eval handler (S0.5) and form extraction (M1.1) run in the same namespace
> and read the same atom. Zed confirmed live (S0.3) to send
> `didOpen` (`version: 0`) → `didChange` → `didClose` per buffer, so the
> input channel is already proven.

## Decisions

| Topic            | Decision                                                                                                                                                           |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Storage          | Extend `zrepl.server`'s state atom: `{:shutdown-received? boolean :buffers {uri {:text :version :language-id}}}`                                                   |
| Sync model       | Full text sync (`textDocumentSync: 1`, already advertised) — `didChange` events carry the whole document, no range patching                                        |
| didOpen          | Stores/replaces the entry wholesale (LSP: re-open of an open doc = reset)                                                                                          |
| didChange        | Applies the **last** event of `contentChanges` (full sync: one event per message; defensive against multi-event batches)                                           |
| didChange w/o    | `didChange` for an unknown uri: ignored with a debug log (spec: only after didOpen; never synthesize a phantom buffer)                                             |
| didClose         | Removes the buffer from the atom (becomes real eviction; today it is a no-op handler)                                                                              |
| didSave          | Registered as a no-op — standard notification on save; with full sync it carries no text, WARN would be pure noise                                                 |
| Concurrency      | Notifications are processed FIFO on the single rpc processing thread; plain `swap!` on the atom, no extra locking                                                  |
| Validation       | Notifications are not validated in `zrepl.rpc` (requests only); schemas document the shape and are asserted in tests                                               |
| Access           | Public read accessors `zrepl.server/buffers` and `zrepl.server/buffer` — used by S0.5 eval, tests, and future CLI/IPC introspection; the atom itself stays private |
| Version tracking | Stored verbatim (`didOpen: version 0`, then per `didChange`); no monotonicity checks in the spike — needed later for stale-result invalidation (M2.3)              |

## Changes

### `src/main/clojure/zrepl/server.clj`

- Initial state: `{:shutdown-received? false :buffers {}}`
- Handlers (replace the `constantly nil` entries):
  - `did-open`: `swap!` → `assoc-in [:buffers uri] {:text, :version, :language-id}`
  - `did-change`: `swap!` → if buffer exists, update `:text` (last change event) and `:version`; else debug log + no-op
  - `did-close`: `swap!` → `update :buffers dissoc uri`
  - `did-save`: no-op
- Accessors:
  - `buffers` — full snapshot `@state` `:buffers` map
  - `buffer` — `(buffer uri)` → `{:text :version :language-id}` or `nil`

### `src/main/clojure/zrepl/lsp/schemas.clj`

- Add `DidCloseTextDocumentParams` (`[:map [:textDocument TextDocumentIdentifier]]`)
- Register `"textDocument/didClose"` in `registry` (documents the shape; used in tests)

### Tests (`src/test/clojure/zrepl/`)

- `server_test.clj`:
  - `buffer-tracking-test`: didOpen → `buffer` returns text/version/languageId; didChange (full text, next version) → text and version updated; didClose → `buffer` returns nil
  - didOpen overwrite resets the entry (same uri opened twice)
  - didChange for unknown uri → no buffer created, no throw
  - didChange with empty `contentChanges` → entry unchanged
  - `notifications-noop-test` gains `textDocument/didSave`
  - didClose/didOpen params validate against the new/registered schemas
- `notifications-noop-test` keeps asserting: handled notifications produce zero output

## Out of scope (later steps)

- Range/incremental sync (full sync is enough for the spike)
- Stale-result invalidation on edits (M2.3 — uses stored `:version`)
- Persistence of closed buffers, output ring buffers (M2.2)

## Acceptance (S0.4 is done when)

1. Unit tests above pass; `mise run lint` and `mise run test` green
2. In live Zed: open/edit/close a `.clj` buffer → no WARNs in zrepl's LSP log
   (all buffer notifications handled), server alive
3. `docs/ai/plan.md` progress log updated; S0.4 checkbox ticked

## Risks

- **Memory churn on large files**: full-sync didChange stores a fresh string per
  keystroke-batch; acceptable for the spike (JVM, buffers bounded by open files)
- **Missed didSave variants**: Zed may send `didSave` with `text` included for
  some languages — we ignore the payload entirely; correctness does not depend
  on it (didChange is authoritative)
- **Restart drift**: if the server restarts mid-session, Zed re-sends didOpen
  for every open buffer (LSP lifecycle), so the atom refills — no action needed
