# S0.2 — LSP skeleton (own JSON-RPC over stdio, no lsp4clj)

> Session decision (2026-09-10): drop `lsp4clj`/`jsonrpc4clj`. The surface we
> need is tiny (~5% of the LSP protocol), and the full stack would drag in
> promesa, core.async, and camel-snake-kebab. We implement framing, dispatch,
> and schemas ourselves, guided by the MIT-licensed `jsonrpc4clj` sources for
> edge cases. Milestone entry in `docs/ai/plan.md` (S0.2) is superseded by this
> document.

## Decisions

| Topic        | Decision                                                                                                    |
| ------------ | ----------------------------------------------------------------------------------------------------------- |
| Transport    | Own JSON-RPC 2.0 over stdio; LSP framing implemented from scratch on JDK 25+ (`readNBytes`, virtual threads) |
| Validation   | `metosin/malli` for our ~5% LSP surface (no `:fn` schemas — keeps GraalVM sci-free)                          |
| JSON         | `metosin/jsonista` (Jackson under the hood)                                                                  |
| Logging      | `org.clojure/tools.logging` + `ch.qos.logback/logback-classic`, programmatic config, **stderr only** — stdout is the protocol stream |
| CLI parsing  | `babashka/cli` — agreed, but added later when the CLI lands (S0.7), not in S0.2                              |
| Concurrency  | Plain threads: virtual-thread reader loop + `ExecutorService` for slow handlers; no core.async, no promesa   |

## Dependencies (`deps.edn`)

- Add to `:deps`: `metosin/malli`, `metosin/jsonista`, `org.clojure/tools.logging`, `ch.qos.logback/logback-classic` (versions via `mise run deps:check`)
- Align/remove logback-classic in the `:develop` alias (it moves to `:deps`; avoid version split)

## Namespaces (`src/main/clojure/zrepl/`)

| Namespace           | Responsibility                                                                                                                                                                                                                                                                                     |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `zrepl.logging`       | Programmatic logback setup (no Joran/XML): `ConsoleAppender` with `target=System.err`; call sites use tools.logging. **Never stdout**                                                                                                                                                                    |
| `zrepl.rpc`           | Framing + message loop. Reader loop on a virtual thread; incoming messages classified as request (method+id) / notification (method only) / response (id, no method). Dispatch table. Write-lock on outgoing messages. Replace `System/out` with a guard `PrintStream` → stderr (like clojure-lsp's `discarding-stdout`) |
| `zrepl.lsp.schemas`   | Malli schemas for our surface: `initialize` (params/result, capabilities), `didOpen`/`didChange` (full sync), `executeCommand`, `inlayHint` request/result; outbound `publishDiagnostics`, `workspace/inlayHint/refresh`, `window/showMessage`                                                                       |
| `zrepl.server`        | State atom; handlers: `initialize` (capabilities: `executeCommandProvider ["zrepl/eval"]`, `inlayHintProvider`, full-text sync), `initialized`/`didOpen`/`didChange` no-op in S0.2, `zrepl/eval` stub returns `{:value "stub"}`, `inlayHint` → `[]`, `shutdown`, `exit` (exit code 0)                              |
| `zrepl.main`          | Entry point for `clojure -M -m zrepl.main`: configure logging, start the rpc loop                                                                                                                                                                                                                          |

## Framing on JDK 25+ (what simplifies vs `io_chan.clj`)

- `InputStream.readNBytes` — exact Content-Length reads instead of a manual loop
- Virtual threads (`Thread/ofVirtual` / `Executors.newVirtualThreadPerTaskExecutor`) for the reader loop and outgoing sends
- No structured concurrency (preview) — plain loops
- Edge cases (peek at `jsonrpc4clj/io_chan.clj`): `\r\n` header termination, `Content-Type: charset=…`, partial reads across buffer boundaries, EOF → graceful shutdown
- Bidirectionality from day one: reader loop must accept client responses to server→client requests (`workspace/inlayHint/refresh`, `window/showDocument`); for the spike we send refresh and ignore the response, but the response channel exists

## Tests (`src/test/clojure/`, tagged `^:unit`)

- Framing: encode/decode roundtrip via `ByteArrayInputStream`/`ByteArrayOutputStream`; malformed headers; fragmented stream (message split across reads)
- RPC dispatcher: routing of request / notification / response
- Integration: scripted stdio JSON-RPC client over pipes — `initialize` → `initialized` → `zrepl/eval` (stub) → `shutdown` → `exit`; assert responses and exit code. This is the S0.2 acceptance gate in `docs/ai/plan.md`

## Acceptance (S0.2 is done when)

1. `clojure -M -m zrepl.main` starts the server; the scripted client completes the full cycle without errors
2. `mise run lint` and `mise run test` are green
3. `docs/ai/plan.md` progress log updated with this revision

## Risks

- jsonista: fewer knobs than cheshire, same Jackson core; native-image (M3) may need reflect-config — revisit in M3, not a blocker now
- Own dispatch: out of scope — cancellation (`$/cancelRequest`), tracing, batching (not in LSP)
